# Admin App (apps/admin)

Platform administration — settlement management, partner oversight, system configuration.

Port 3003. Requires `sudo: true` on User record.

## Key Responsibilities

- **Settlement management**: Review and approve monthly partner payouts (DRAFT → CLOSED → APPROVED → PAID lifecycle)
- **Invoice oversight**: View and audit invoices and invoice lines generated by the payment system
- **Partner management**: Platform-level partner account visibility
- **System settings**: Global service fee configuration (the fallback tier in the three-tier fee cascade)

### Known Issues Flagged by Tests

- **Weak email validation** in `addAdminUser`: only checks for `@` — `"a@b"` passes (no TLD/format check)
- **Inconsistent error shapes**: `users/actions.ts` and `sites/actions.ts` use `{ error: string }` (singular), while `settlements/actions.ts`, `fees/actions.ts`, `platform/actions.ts` use `{ errors: string[] }` (plural)
- **Inconsistent requireSudo error messages**: `users/actions.ts` throws `'sudo required'`, `settlements/actions.ts` throws `'Unauthorized — sudo required'`
- **No self-removal protection** in `removeAdminUser` — admin can remove their own access
- **Redundant DB query** in `deleteUser`: makes 3 separate `findUnique` calls (requireSudo + user details + sudo check on target — last two could be combined)
- **No mutual exclusivity** in `saveServiceFee`: both `feeAmount` and `percentage` can be set simultaneously
- **No bounds validation** on fee values: negative `feeAmount` and `percentage > 100` are accepted
- **Unknown chargeType accepted**: arbitrary strings like `'bogus'` pass validation (only `'fixed'` and `'percentage'` have value checks)
- **No duplicate check on service code update**: `saveServiceCode` only checks for duplicates on create, not update
- **No referential integrity check** in `deleteServiceCode`: unlike `deleteSettings` which checks for referencing fees, `deleteServiceCode` does not
- **Duplicate country settings**: no uniqueness check when creating settings for same country
- **Password validation mismatch**: `reset-password` API route validates `>= 6 chars` but `@repo/data/password-reset` enforces `8+ chars with upper+lower+digit` — misleading API error message
- **No siteId validation** in `updatePaymentProvider`: empty string goes to DB without check
