## Goal

Move every production web app (`admin`, `marketing`, `partner`, `user`) from **Next 14.2.35 /
React 18.3.1** to **Next 16.4 / React 19.x**, one app at a time, with every intermediate state
deployable. Out of scope: MUI 5→7, Tailwind 3→4, Prisma, `apps/mobile` (already React 19.2.3).

Plan of record: `~/.claude/plans/plan-upgrade-to-latest-ticklish-snail.md` (approved 2026-10-10).

## Resume here

- **State:** ALL FOUR web apps on Next 16.4 / React 19.3. admin + marketing pushed (`539acb9`); partner (`8790ef2`, `d755480`) and user (`e56e44d` + S4 B) committed, **not pushed**.
- **Next action:** push when the founder asks → check the partner/user previews. Then S5: remove the five root old-stack pins (`next`, `react`, `react-dom`, `next-auth`, `next-intl`, `@mui/material-nextjs`) so the root hoists the new stack; re-verify every app's co-location + builds.
- **Carry forward to S3/S4 (MUI apps):** add `AppRouterCacheProvider` from `@mui/material-nextjs/v16-appRouter` (v9.5, MUI-version-agnostic) around the root layout, or every page fails hydration under Next 16. Also add `allowedDevOrigins: ['local.sunbnb.app']`.
- **Watch — co-location invariant:** each app's `next` must resolve the SAME `react` as the app, and every Next-coupled package (`next-auth`, later `next-intl`) must resolve the app's own `next`. The root `devDependencies` pin the OLD stack (`next@14.2.35`, `react`/`react-dom@18.3.1`, `next-auth@5.0.0-beta.30`, `next-intl@3.26.5`, `@mui/material-nextjs@5.18.0`), so a migrated app nests its new versions together. A migrated app must request a version DIFFERENT from the root pin for every coupled package, or npm dedupes it to the root. Check with the resolve one-liner in the S1 log. Remove the pins in S5.
